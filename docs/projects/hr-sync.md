# 项目任务书：教务同步（本系统侧）

> 面向维护此功能的 AI agent / 开发者。决策与否决理由见 `docs/adr/0008-hr-sync-consumer.md`，本文讲做了什么、怎么接通。

## 1. 范围

**只做本系统这一侧，教务（`../hr-management`）一行不改。**按教务现有集成接口 `/api/integrations/online-form/v1` 的形状写消费端，全部开发测试对着本地 mock（`epq-tutor-backend/tests/hr_mock.py`）。

接通真实教务只差教务侧一个改动：认一个本系统专用的 service token（见 §6）。

## 2. 非目标

- **不调教务的 ack 端点**（会挪动在线表单系统的位点，ADR 0008 决策 1）
- **不做后台自动同步**——导师手动触发，预览确认后落库
- **不同步督导**——教务分配里的英方 SA（`1_000_000+` 段）其实就是本系统的 `supervisors`，留作后续
- **不同步学校 / 年级 / 性别 / 报名学期**——教务接口里没有

## 3. 组成

| 文件 | 作用 |
|---|---|
| `app/hr_client.py` | 只读客户端。**刻意没有 ack 方法**，测试断言这一点 |
| `app/hr_sync.py` | 引擎：`refresh_mirror` 全局增量拉镜像 / `preview_for` 按导师出预览 / `apply_for` 按导师落库 |
| `app/routers/hr_sync.py` | 导师侧端点：`status` / `preview` / `apply` |
| `app/routers/admin.py` | 管理侧：`hr-config`、`hr-sync/refresh`、`hr-people`；`PATCH /tutors/{id}` 支持 `hrUserId` |
| 迁移 `0007_hr_sync` | `tutors.hr_user_id`、`students.hr_student_code`（唯一约束 `(tutor_id, code)`）、`hr_projects` 镜像表 |
| `tests/hr_mock.py` | 教务接口复刻，逐条照搬响应形状与合成 id 规则；可独立运行 |
| 前端 `HrSyncPage` / `HrConnectionSection` | 导师同步页；管理面的连接配置 + 关联下拉 |

## 4. 流程

1. **管理员**在「账号管理」填教务地址和 token → 「立即拉取」→ 教务老师名单出现在每行的「教务账号」下拉里（只列真实账号，合成 id 和 IM 不在列）→ 给导师逐个关联。
2. **导师**在 Dashboard 点「从教务同步」（只在教务已配置且本人已关联时出现）→ 后端先增量刷新镜像（10 分钟冷却）→ 逐行预览：新建 / 更新 / 关联已有 / 需确认，教务退出的单独标红 → 确认后落库。

## 5. 过程中顺带修掉的一个既有 bug

**「换轮次清旧截止安排」（ADR 0003）只在 `save_student` 里实现了**，Excel 导入和本次的教务同步都直接 `setattr` 绕了过去——旧轮次的「已延期一周」会被带进新轮次。收成 `submission.set_submission_round()`，三条写入路径都走它；Excel 导入那条补了回归测试。（resit 要清的更多，仍单独处理。）

## 6. 接通真实教务需要什么

教务侧：`require_service_token` 目前只认一个 `ONLINE_FORM_SERVICE_TOKEN`。需要让它也认一个本系统专用的 token（新增一个配置项 + 一行比较即可）。**ack 端点不需要改**——本系统不调它。

本系统侧：管理面填上教务地址和那个 token。不需要改代码。
