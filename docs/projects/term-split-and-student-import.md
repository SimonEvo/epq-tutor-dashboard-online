# 项目任务书：学期拆分 + 学生 Excel 导入

> 面向维护此功能的 AI agent / 开发者。术语沿用根 `CLAUDE.md`。轮次模型的决策与否决理由见 `docs/adr/0005-registration-vs-submission-round.md`，本文只讲怎么做和做了什么。

## 1. 目标

复现教务系统（`../hr-management`）的两项能力：**报名/提交学期拆分（含一年期自动推导）** 和 **学生批量导入**。两者都做完了。

## 2. 非目标

- **不复现教务的长标签格式** `25秋季（26年3月提交）`。解析器认它，存储归一为 `25秋`。
- **不复现姓名字符串嗅探作为领域逻辑**（ADR 0005 决策 3）。
- **不做粘贴导入**。教务同时有粘贴和 Excel 两条路径；这边只做文件上传，少一套解析代码。
- **导入不碰关联数据**。只写学生档案字段，不动 sessions / 里程碑 / 作业 / 知识库。
- **不做导出**。

## 3. 学期拆分

### 数据模型（迁移 `0003_registration_round`）

```
students + registration_round VARCHAR(64)   签约批次，不随延期变动
students + is_one_year BOOLEAN NOT NULL     一年期学制
students   submission_round                 （已有）提交批次，一年期顺延、延期可改
```

存量 19 名学生回填 `registration_round = submission_round`，全部普通学制。

### 推导规则（`app/rounds.py` / `src/lib/rounds.ts`）

下一轮：**春 → 同年秋；秋 → 次年春**。提交批次 = 一年期 ? 下一轮 : 同轮。

一年期的起始轮次解析有**优先级**，照搬教务 commit `d15079a` 修好之后的版本：

1. 先看班期/姓名里有没有 `25秋一年期` 这类**起始学期前缀**，有就用它；
2. 取不到才退回「报名轮次 +1」。

教务最初只有第 2 条，班期带前缀时会算错。复现时若只抄最终函数、漏掉这个次序，就把那个 bug 一起抄回来了。测试 `test_one_year_base_round_beats_naive_increment` 专门钉住这一点。

前后端各有一份实现：后端是权威（导入和保存都会归一），前端只用于编辑表单预填，算错最多预填不准，不会写坏数据。

### 界面

编辑/新建页把原来单个「Submission Round」拆成两个字段 + 一年期勾选框。改报名轮次或勾选一年期会**联动**重算提交轮次；提交轮次与推导值不符时显示「已手动改动（延期）」。

联动只写在 onChange 里，**不用 effect** —— effect 会在打开编辑页时把延期学生手工改过的值冲掉。

## 4. Excel 导入

### 分工

解析在**前端**（`src/lib/studentExcelParser.ts`，xlsx 库）：文件不必上传，后端不处理二进制。后端（`app/routers/student_import.py`）只收结构化行，负责匹配、算差异、落库。

### 表头自动识别

不依赖固定列顺序 —— 教务导出的表列序常变。每个字段一组别名，对**前 15 行**逐行打分找表头行（样例表第一行是标题、第二行才是表头，已验证能跳过）。打分：完全相等 > 表头包含别名 > 别名包含表头，长别名优先。

### 三条规则

1. **空单元格不覆盖已有数据。** 导入表往往只含部分列，把空值当"清空"会静默抹掉纪要、备注这些表里根本没有的字段。只有非空值才进 diff、才写库。
2. **匹配靠姓名（归一后）。** 本系统没有学号也没有邮箱。命中多条或批次内重名一律标 conflict 交人工判断，绝不自动合并。
3. **冲突行默认跳过**，无变化的更新行也默认跳过。

### 流程

选文件 → 选工作表（多表时）→ 解析结果（行数 + 识别到的列）→ 与现有学生比对 → 逐行确认（新建/更新/跳过，更新行展开字段级 before→after）→ 应用。

督导按姓名在**本租户内**查找；查无此人或同名多位时给警告并留空，不阻断导入。

### 与多租户的关系

导入端点走 `scoped()`，新建学生带 `tutor_id`，更新时按租户查找目标。`test_apply_refuses_other_tenants_student` 钉住"拿别人的学生 id 来更新"回 404。

## 6. 过程中抓到的两个问题

1. **性别词表不一致。** 解析器原本把性别归一成「男/女」，但本系统的规范值是 `Male`/`Female`/`Other`（界面才显示中文，见 `StudentFormFields` 的 option value）。写成中文会让表单下拉选不中，且一次导入就把全库取值搞成两套。浏览器里看到一条 `性别 Male → 男` 的虚假 diff 才发现。
2. **归档轮次在编辑页丢失。** 一年期学生的提交批次可能落在已归档的轮次上，该轮次不在 `/api/config/rounds` 返回的列表里。`<select>` 的 value 找不到对应 option 会渲染成空白，**一保存就把轮次抹掉**。已改为当前值始终出现在选项中。

## 7. 依赖说明

`xlsx` 装的是 **SheetJS 官方 CDN 的 0.20.3**，不是 npm 上的 0.18.5：

```
"xlsx": "https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz"
```

npm 上的 0.18.5（教务用的版本）带两个 high 级公告 —— 原型污染（<0.19.3）和 ReDoS（<0.20.2），且 `fixAvailable: false`，因为 SheetJS 从 0.18.5 之后不再发布到 npm。换成 CDN 版后 `npm audit` 里 xlsx 相关条目清零。

代价：`npm install` 需要能访问 `cdn.sheetjs.com`。`deploy.py` 只在本地构建前端，所以仅开发机受影响。

## 8. 遗留

- **一年期只能导入时打标、不能取消。** `isOneYear=false` 被当作"没提供"，否则任何一张没有该列的表都会把标记洗掉。取消需去编辑页手动改。
- **与教务的春季提交月份口径不一致**（教务 9 月 / 本系统 8 月），见 ADR 0005。对接前需确认。
- **轮次写入已限定 admin**（ADR 0004），但前端还没有角色概念，普通导师点编辑页的「Add」加新轮次会收到 403 且无友好提示。归入 P2 管理后台一并处理。
